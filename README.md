# Scythe

할아버지 땅의 예초를 대신할 로봇을, 실물을 만들기 전에 시뮬레이션으로 먼저 검증하는 프로젝트입니다.

부품은 아직 하나도 사지 않았습니다. 물리 엔진 위에 궤도 차체를 세우고, 경사에서 미끄러지고 넘어지는 지점을 찾고, 제어 로직을 붙이고, 마지막에 실물 STM32를 가상 차체에 연결하는 순서로 갑니다.

---

## 이름 규율

실물과 연결되고 실측으로 보정되기 전까지는 **디지털 트윈이 아니라 시뮬레이션**입니다. MIL → SIL → HIL → 실물 순서로 올라가고, 각 단계의 이름을 앞당겨 쓰지 않습니다.

같은 이유로 **이 레포의 숫자는 절대값이 아니라 비교로만 읽습니다.** 풀 절삭은 물리 엔진이 못 푸는 영역이라 외란 힘으로 가정해서 넣고, 마찰계수와 무게는 추정값입니다. "경사 22도에서 미끄러진다"가 아니라 "A 구성이 B보다 덜 미끄러진다"까지가 이 레포가 말할 수 있는 것입니다. 절대값은 현장 실측으로만 맞춥니다.

---

## 왜 만드나

할아버지가 여든다섯인데 아직 청도까지 한 시간을 운전해 가서 제초를 하십니다. 풀이 사람 허리까지 자라는 땅이라 제초는 선택이 아닙니다. 실제로 가서 하는 건 저고, 숙련자 기준 2시간짜리 면적입니다. 로봇이 있으면 그 2시간이 제 몸에서 빠집니다.

기대치는 분명히 해둡니다. **얻는 것은 속도가 아니라 몸이 그 자리에 없어도 되는 것입니다.** 소형 원격 제초기로 바꾼다고 2시간이 30분이 되지 않습니다.

## 단계

| # | 질문 | 산출 | 상태 |
|:-:|------|------|:----:|
| 0 | 궤도 차체가 평지에서 조종대로 움직이나 | 키보드로 모는 모델 | |
| 1 | 경사 × 무게 → 어디서 미끄러지고 뒤집히나 | 무게 하한 | |
| 2 | 풀 반력을 넣으면 모터·배터리가 2시간 버티나 | 동력 예산 | |
| 3 | 풀 속 돌에 걸리면 날이 몇 ms 만에 멈추나 | 날 부하 감지 정지 | |
| 4 | 조종 링크가 끊기면 어디서 서나 | 워치독 값 | |
| 5 | 실물 STM32를 가상 차체에 연결 | HIL | |

각 단계는 앞 단계가 검증된 뒤에만 시작합니다. 뒤 단계가 깨져도 앞 단계는 돌아가야 합니다.

## 설계 전제

- **절삭은 엔진, 주행은 전동.** 취향이 아니라 계산 결과입니다. 억센 풀 절삭을 2시간 하면 3kWh가 필요한데 리튬으로 담으면 팩만 20kg이 넘습니다. 저속 궤도 주행은 같은 시간에 1kWh 이하입니다.
- **RC카 베이스가 아니라 궤도 스키드 스티어.** RC카는 가볍고 빠르도록 최적화된 물건인데, 여기 필요한 건 무겁고 느리고 토크가 큰 쪽입니다. 억센 풀은 반력이 커서 가벼우면 풀이 기계를 밉니다.
- **무게 상한 → 구동계 → 프레임 → 헤드 → 전자** 순서로 정합니다. 거꾸로 가면 무게를 감당하지 못합니다.

## 관련 저장소

- **[Neuro-Drive](https://github.com/steppenhj/Neuro-Drive)** — RPi5 + STM32 분산 UGV 제어. 이 프로젝트의 제어 구조(ISR→Queue→Task, 2중 워치독, fail-stop)가 여기서 옵니다.
- **[multi-mcu-can](https://github.com/steppenhj/multi-mcu-can)** — 2노드 CAN 2.0 통신. Phase 5 HIL에서 PC(물리 모델) ↔ STM32(제어기)를 잇는 물리 계층이 됩니다.
